# 我的 AI 简报系统，昨天免费升级了

我的 AI 简报系统每天在抓信号。多个 Agent 各司其职，爬网页、读推文、整理数据，最后汇总成一份我每天早上读的情报简报。

昨天 Anthropic 推了一个更新，我第一反应不是"这功能好"，而是掐着手指算：**我的系统今天是不是变好了，但我没做任何事？**

答案是：是的。

## 加一行代码，免费涨价

Anthropic 升级了 Claude 的 web search 和 web fetch 工具。改进的核心不是"搜索算法更好了"，而是机制变了。

旧做法是：把整个网页的 HTML 塞进 Claude 的上下文，让它自己去推理哪些信息有用。一个网页的完整 HTML 里有多少噪音——导航栏、Cookie 弹窗、广告、各种 class 和 div——Claude 得先把这些全部读完，再从里面找到真正有价值的内容。

新做法是：Claude 先自动写一段代码，把无关内容过滤掉，再把干净的结构化信息加载进来推理。

数据结果：精准度平均提升 11%，输入 token 减少 24%。在需要多步推理的复杂研究任务上，Sonnet 4.6 从 33.3% 涨到 46.6%，Opus 4.6 从 45.3% 涨到 61.6%。

对我来说，这意味着：加一行 API beta header，我的简报系统就能用上这个能力。成本降 24%，信号质量提升。**没花一分力气，白得一次系统升级。**

## 但更重要的不是省钱

我用简报系统有一段时间了。一直觉得 web fetch 的问题是"网页太乱"——信息密度太低，Claude 从一堆噪音里提取出来的东西，质量参差不齐。

我以为这是模型理解能力的问题。

这次更新让我意识到：**不是 Claude 不够聪明，是我在用推理能力做数据清洗。**

推理能力应该用在判断和决策上，不应该用来解析脏数据。把 HTML 噪音塞给模型，让它既要理解格式、又要提取内容、又要做分析——这件事从一开始就分工混乱。

新范式把这件事拆开了：先用代码过滤数据，再让模型做推理。两件事各自做好自己的。

这个思路值得横向应用。我在做的 GBaseGTM 是一个 500 万日本企业的数据库产品，用户输入自然语言，系统返回相关企业列表。现在的实现是把查询结果直接交给模型去理解和排序——也就是让推理层处理原始数据集。

**按新范式，应该先让 Agent 写代码做一轮过滤和排序，再把结构化结果交给推理层。** 这是下一步要做的实验，估计效果会明显。

## Anthropic 悄悄补完了最后一块

这次更新还有一个细节值得注意：同一时间，五个功能一起进入了 Generally Available 状态。

- Code execution（代码执行）
- Memory（记忆）
- Programmatic tool calling（可编程工具调用）
- Tool search（工具搜索）
- Tool use examples（工具使用示例）

单独看每一个，都是"又一个新功能"。合在一起看，感觉不太一样。

我做 Shipyard 这个内容系统，用了一套自己搭的文件记忆系统——用 Markdown 文件记录每次生成的内容、做了什么决策、发现了什么模式。这是我从一开始就认定"Agent 需要记忆"、然后自己动手实现的东西。

Memory 正式 GA，说明这个方向是对的。Anthropic 在用行动告诉开发者：记忆是 Agent 的标配，不是可选项。

> 我一直觉得，做 AI 产品最难的部分不是调用 API，而是设计 Agent 的工作流——它怎么记住事情、怎么知道该用什么工具、怎么在多步任务中保持一致性。这些问题比"选哪个模型"重要得多。

Tool search GA 对我的 Skill 系统也是个信号。我现在的调用方式是静态的——在配置里写好"什么情况用什么 Skill"。本质上是人工编排，而不是 Agent 自主决策。

Tool search 让 Agent 能在运行时动态发现可用工具。未来，Skill 可以注册为动态可发现的能力，Agent 自己判断需要什么，而不是靠我事先写死。这是一个值得认真规划的架构方向。

## 这几个月那个问题有答案了

这段时间一直有人问：Agent 到底什么时候真正能用？

我自己之前的判断是：理论上能用，但基础设施还差一口气。现在这口气补上来了。

Memory、代码执行、动态工具发现、可编程调用——这几件事凑在一起，Anthropic 其实在发一个信号：**生产级 Agent，现在可以认真做了。**

不是实验级，不是 beta，是 GA。

对我来说，实际的影响是：可以更踏实地规划下一阶段的架构，不用再一直在 beta feature 和临时方案之间腾挪。

这周我会先做一件小事：**开启动态过滤的 beta header，观测简报系统的信号质量变化。** 如果有明显改善，再决定要不要在 GBaseGTM 的搜索层做类似的重构。

小步走，但方向清楚了。
