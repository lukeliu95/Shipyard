# 我在简报里看到了三个产品机会

每周看 AI 简报，我习惯问自己一个问题：**这些信号里，藏着什么我能做的东西？**

今天分享三个从信号里"挖"出来的产品洞察。

---

### 信号一：Vibe Coding 三个月后没人看得懂

Red Hat 发文说，AI 生成的代码三个月后变成"唯一真相来源"——代码能跑，但没人知道当初为什么这么写。

**产品洞察：代码考古工具**

如果代码是 AI 写的，那"理解代码"就变成了一个独立的需求。

想象一个产品：你把代码库丢进去，它告诉你这段代码在做什么、为什么这么做、当初的设计决策是什么。不是简单的注释生成，而是**反向工程 AI 的思考过程**。

谁会买？接手 AI 代码库的工程师、做代码审计的安全团队、需要维护遗留系统的外包公司。

**为什么现在是时机？** Vibe Coding 刚爆发几个月，大量 AI 代码还没到"三个月后"的维护期。但很快，这个痛点会集中爆发。

---

### 信号二：非工程师用英语定义 Agent 行为

Ramco 发布了 Chia 平台，卖点是 NLW（Natural Language Workflow）——不用写代码，用英语描述你要什么，系统翻译成 Agent 的行为逻辑。

**产品洞察：Agent 的"无代码"层**

SoftBank 已经部署了 250 万个 Agent。但大多数公司没有 SoftBank 的工程能力。

真正的大市场不是"帮工程师造 Agent"，而是"帮非工程师用 Agent"。

想象一个产品：HR 用自然语言描述"帮我筛选简历、安排面试、发 follow-up 邮件"，系统自动组装出这个工作流。不需要理解什么是 MCP、什么是 prompt engineering。

**为什么现在是时机？** Agent 采用率刚到 15-23%（arXiv 数据），早期采用者是工程师。下一波采用者是非技术团队，他们需要的是"能用"而不是"可定制"。

---

### 信号三：45 亿教用户写 prompt，留存是关键

中国四大厂砸 45 亿教用户 prompt engineering。2-4 周后的留存数据是验证点。

**产品洞察：Prompt 模板库 + 效果追踪**

如果 45 亿砸下去，留存不好，说明什么？**用户不想学 prompt engineering，他们只想要结果。**

与其教用户写 prompt，不如直接给用户"能跑的 prompt 模板"。

想象一个产品：你选一个场景（比如"写周报"、"做竞品分析"、"生成营销文案"），系统给你最优的 prompt 模板，并且追踪每个模板的实际效果——点击率、完成度、用户满意度。

**为什么现在是时机？** 中国的 45 亿实验 3 月初出结果。如果留存数据不好，就是"prompt 教育"路线失败的信号，"prompt 即服务"路线的机会就来了。

---

### 怎么从信号里挖产品机会

我的方法很简单，三步：

**第一步：找到痛点**

信号里凡是提到"问题"、"危机"、"触墙"、"失败"的，都是痛点。

- Vibe Coding 触墙 = 代码可维护性痛点
- 生产力悖论 = AI 工具没解决实际问题
- 45 亿红包留存未知 = 用户教育成本高

**第二步：问"谁在疼"**

每个痛点背后都有一群人在疼。找到他们，就找到了用户。

- 谁在疼 Vibe Coding 的维护问题？接手代码的工程师。
- 谁在疼 Agent 太难用？想用但不会写的业务团队。
- 谁在疼 prompt 太复杂？被 45 亿教育但学不会的普通用户。

**第三步：问"现在为什么能做"**

时机比想法重要。

- Vibe Coding 刚爆发，维护危机还没到 = 提前布局
- Agent 采用率 15-23% = 从早期采用者走向大众的拐点
- 45 亿实验结果将出 = 等结果再入场也来得及
