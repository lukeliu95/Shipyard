# memory/ — 持久记忆系统

Shipyard 的大脑。所有的历史记录、决策逻辑、模式积累都在这里。
纯 Markdown 文件实现持久记忆——可读、可搜、可版本控制。

---

## 目录结构

```
memory/
├── index.md          ← Tier 1 总入口（每次会话必读）
├── README.md         ← 你正在读的这个
├── content-log.md    ← 完整内容生产记录（Tier 3，按需下钻）
├── decisions.md      ← 内容决策 why（Tier 3，按需下钻）
├── patterns.md       ← 可复用模式积累（Tier 2，生成内容时参考）
└── weekly-state.md   ← 本周运营状态（Tier 2，按需读取）
```

---

## 渐进式读取设计

这套系统的核心原则是：**LLM 不应该每次都读所有文件。**

```
Tier 1 — 必读（每次会话启动）
  └─ index.md
       包含：统计摘要 + 本周快照 + 最近5条内容 + 读取指引
       读完此文件，可判断是否需要继续下钻

Tier 2 — 按需读取（根据任务需要）
  ├─ weekly-state.md   需要本周进度细节时
  └─ patterns.md       生成内容时，参考写法模式

Tier 3 — 精准下钻（仅在明确需要时）
  ├─ content-log.md    需要完整生产记录、详细去重时
  └─ decisions.md      遇到类似决策时参考
```

---

## 各文件说明

### index.md — 总入口（Tier 1）

**每次会话必读，也只需要先读这一个。**

包含内容：
- 渐进式读取指南（告诉 LLM 该读哪些文件）
- 统计摘要（总内容数、各平台分布）
- 本周快照（产出进度表）
- 最近 5 条内容（快速去重参考）
- 完整记忆文件索引

---

### content-log.md — 内容生产记录（Tier 3）

**核心记忆文件。每次生成后追加一条记录。**

每条记录包含：
- 编号 ID、日期、平台、内容线
- 标题/slug、输入素材来源
- 使用的 Skill、前置分析情况
- 关联内容（跨平台联动追踪）
- 当前状态（draft → published）
- 决策备注（为什么这样写）

**去重规则：**
- 同一信号源 7 天内不重复使用
- 同一产品决策不在同一平台重复发布
- 同一方法论主题 30 天内不重复

---

### decisions.md — 决策记录（Tier 3）

**记录每次内容生产中的关键判断：为什么选这个角度，为什么放弃某个方向。**

每条记录格式：
```
场景：什么情况下做的决策
选择：选了什么
放弃：放弃了什么
原因：为什么
```

随实践积累，帮助 Shipyard 建立内容判断力，避免反复犯同样的错误。

---

### patterns.md — 模式积累（Tier 2）

**从多次内容生产中提炼的可复用写法模式。**

三个维度：
1. **素材→平台匹配模式** — 什么类型素材适合什么平台
2. **高效写法模式** — 什么角度/结构效果好
3. **踩坑记录** — 什么写法要避免

生成内容前可快速扫描，挑选匹配当前任务的模式。

---

### weekly-state.md — 本周状态（Tier 2）

**每周一重置。追踪本周内容生产进度和素材队列。**

包含：
- 本周产出进度（各平台目标 vs 已完成）
- 待处理素材队列（含状态流转）
- 待推进选题 todo 列表
- 本周节奏规划

---

## 更新时机

| 触发事件 | 需要更新的文件 |
|---------|--------------|
| 生成一篇内容后 | content-log ✦ index（统计+最近5条）✦ weekly-state |
| 做出关键决策后 | decisions |
| 发现新写法规律后 | patterns |
| 每周一 | weekly-state（重置）|
| 每月初 | patterns（提炼）|

---

## 设计原则

**文件即数据库** — 不依赖任何外部系统，Markdown 文件就是记忆载体。
**渐进式读取** — index.md 是入口，避免每次读全量文件浪费上下文。
**只追加不修改** — content-log 和 decisions 只追加新记录，保留完整历史。
