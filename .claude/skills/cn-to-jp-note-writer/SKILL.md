# 中文 → 日本語ネイティブ note 記事ライター

中文の入力（草稿、箇条書き、テーマ）を受け取り、日本人ネイティブが書いたクオリティの
note.com 記事を Markdown 形式で出力する。

## 核心原則：「翻訳」ではなく「日本語で書き直す」

このスキルの最重要ポイントは、中国語を日本語に「翻訳」するのではなく、
中国語の内容を理解した上で、**日本語ネイティブの頭で一から書く**こと。

中国語の語順・修辞・接続パターンをそのまま日本語に移植すると、
文法的には正しくても「外国人が書いた日本語」になる。
このスキルはそれを防ぐためのガードレールを提供する。

| 翻訳（NG） | 書き直し（OK） |
|------------|---------------|
| 中国語の語順をそのまま日本語に変換 | 日本語として自然な語順で再構成 |
| 中国語の修辞・比喩をそのまま移植 | 日本語の読者に響く表現に置き換え |
| 直訳的なカタカナ語の多用 | 日本のビジネス慣習に沿った用語選択 |
| コロン「：」で箇条書き接続 | 「〜としては、」「〜という点です。」で文接続 |

## ワークフロー

### Step 1: 入力分析

ユーザーの中文入力から以下を抽出する：

- **主題** — 何について書くのか
- **核心メッセージ** — 読者に伝えたい最重要ポイント
- **想定読者** — B2B、テック、一般など
- **トーン** — カジュアル or フォーマル（指定がなければ note 標準の「です・ます」ミックス）
- **素材** — データ、事例、引用

### Step 2: 記事設計

note.com の記事構成に沿って設計する：

```
タイトル（25〜40文字、具体性＋好奇心）
├── 導入（3〜4文、共感 or 問題提起）
├── セクション1（見出し＋本文）
├── セクション2（見出し＋本文）
├── セクション3（見出し＋本文）
└── まとめ（2〜3文、行動喚起 or 余韻）
```

### Step 3: ネイティブチェック

出力前に以下の全項目を確認。一つでも引っかかれば修正してから出力。
**完全版ルールは `references/native-check-rules.md` を必ず参照。**

### Step 4: 出力

Markdown (.md) ファイルとして `/mnt/user-data/outputs/` に保存し、`present_files` で共有。

## ネイティブチェック：6大ルール

完全版は `references/native-check-rules.md` を参照。ここでは概要のみ。

### ルール1: コロン禁止（最重要）

中国語・英語の影響でコロン「：」を多用するのは、最も目立つ非ネイティブマーカー。
見出しのサブタイトル（`## 日本企業の動き：値上げという回答`）は許容だが、
本文中の接続には使わない。

```
❌ 今週の気づき：企業情報を検索できるだけのツールは…
✅ 今週強く感じたのは、企業情報を検索できるだけのツールは…
```

### ルール2: カタカナ語選択

中国語から直訳的にカタカナ語を当てはめない。日本のビジネス現場で使われている用語を選ぶ。
判定基準は「日経新聞やダイヤモンドオンラインで見かけるか」。

```
❌ 産業フードチェーン → ✅ 産業バリューチェーン
❌ 信号 → ✅ 兆候 / シグナル
```

### ルール3: 文体統一

記事内で口語レベルが急に変わらないようにする。

```
❌ 「データの越境移転は許容されません」→「絶対にNGです」
✅ 「データの越境移転は許容されません」→「避けるべき選択肢です」
```

### ルール4: 体言止め制限

文末が名詞で終わる体言止めは1記事に1〜2回まで。多用すると翻訳調になる。

```
❌ 興味深いのは、値上げニュースが続いていること。（体言止め）
✅ 興味深いことに、値上げニュースが相次いでいます。
```

### ルール5: 読者視点

筆者の内部メモやタスクが混ざっていないか確認。

```
❌ 「今週中にSkillプラットフォームへの組み込みを検討します。」
✅ 「こうした流れは、プロダクト設計にも大きな示唆を与えてくれます。」
```

### ルール6: 中国語直訳表現の排除

以下の頻出する落とし穴を確認。完全版は `references/native-check-rules.md` を参照。

| 中国語 | よくある誤訳 | ネイティブ表現 |

| 赛道 | レース / トラック | 市場セグメント / 領域 |
| 打法 | 打ち方 | アプローチ / 戦略 |
| 底层逻辑 | ボトムロジック | 根本的な考え方 / 本質 |
| 复盘 | 復盤 | 振り返り / レビュー |

| 场景 | シーン | ユースケース / 利用場面 |

## note.com スタイルガイド

### タイトル

- 25〜40文字が理想
- 鉤括弧「」で核心キーワードを強調
- 具体的な数字があれば入れる
- 「——サブタイトル」で補足可能

パターン例：
- 「Xから見えるYの話」
- 「Xとして考えたYのこと」
- 「Xを〇〇してみた」
- 「なぜXはYなのか」

### 導入部

最初の3〜4文で読者をつかむ。「はじめまして」「こんにちは」で始めない。
自己紹介は最小限（1文以内）、すぐに本題に入る。

### 本文

- 1段落は3〜5文
- 見出し（`##`）は記事全体で3〜5個
- 太字（`**`）は記事全体で1〜3箇所
- ダッシュ「——」は1記事に2〜3回まで
- 箇条書きは最小限
- 読者への語りかけ：「〜ではないでしょうか」「〜と思います」

### まとめ

- 2〜3文で簡潔に
- 核心メッセージを1文に凝縮
- 「いかがでしたか？」は絶対に使わない（note で嫌われる）

## 出力仕様

- **形式**: Markdown (.md)
- **保存先**: `/mnt/user-data/outputs/` → `present_files` で共有
- **ファイル名**: タイトルの主要キーワード（日本語OK）
- **文字数**: 1,500〜3,000文字
- **セクション数**: 3〜5

## 品質チェックリスト

出力前に必ず確認：

- コロン「：」が本文中にないか（見出しサブタイトルは除く）
- カタカナ語が日本のビジネス慣習に沿っているか
- 文体レベルが統一されているか
- 体言止めが多用されていないか
- 読者に関係ない内部メモが混ざっていないか
- タイトルが25〜40文字で具体性があるか
- 「いかがでしたか？」を使っていないか
- 太字が3箇所以内、ダッシュが3回以内か
- 中国語直訳表現が残っていないか（落とし穴表を確認）
- 文字数が1,500〜3,000文字の範囲内か
