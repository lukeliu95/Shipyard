# ネイティブチェックルール完全版

日本語ネイティブが書いた文章かどうかを判定するための詳細ルール集。
出力前に全項目を確認し、一つでも該当すれば修正する。

## 目次

1. 句読点・記号の使い方
2. 語彙・カタカナ語

## 1. 句読点・記号の使い方

### 1.1 コロン「：」の本文使用禁止

**深刻度: 高（最も目立つ非ネイティブマーカー）**

中国語・英語では「Title: content」のようにコロンで接続するのが普通だが、
日本語の文章ではコロンを本文中で使うことは極めて稀。

**許容されるケース：**
- 見出しのサブタイトル: `## 日本企業の動き：値上げという回答`
- 技術文書のパラメータ: `max_retries: 3`
- 時刻表記: `13:00`

**本文中の変換パターン：**

| コロン使用パターン | 日本語ネイティブ表現 |
|-------------------|-------------------|
| `Xの気づき：Y` | `Xとして感じたのは、Y` |
| `重要なポイント：Y` | `重要なのは、Yという点です。` |
| `もう一つ：Y` | `もう一つあります。Y` |
| `結論：Y` | `結論として、Y` / `つまり、Y` |
| `理由：Y` | `その理由は、Y` / `なぜなら、Y` |

### 1.2 ダッシュ「——」の使い方

1記事に2〜3回まで。効果的な使用例：

```
✅ 下流（SaaS、物流仲介）は二重の打撃——コスト増とAI代替の恐怖。
```

### 1.3 丸括弧「（）」の使い方

1段落に2回以上は多すぎる。括弧の代わりに文を分ける。

```
❌ 日本のB2B企業（特に製造業）は、AI（人工知能）を活用して…
✅ 日本のB2B企業、とりわけ製造業は、AIを活用して…
```

## 2. 語彙・カタカナ語

### 2.1 中国語直訳カタカナ語の回避

判定基準：日経新聞・東洋経済・ダイヤモンドオンラインの記事で見かけるかどうか。
見かけないカタカナ語は和語や定着済みのビジネス用語に置き換える。

### 2.2 和語 vs カタカナ語のバランス

カタカナ語が3つ以上連続すると読みにくくなる。

```
❌ イノベーティブなソリューションをインプリメントする
✅ 革新的な解決策を導入する
```

ただし定着済みのカタカナ語はそのまま使う：
SaaS, API, AI, インサイト, バリューチェーン

### 2.3 「〜的」の多用回避

「〜的」は1文に1回まで。

```
❌ 構造的な再評価を戦略的に実行する必要がある
✅ 構造の見直しを、戦略を持って進める必要がある
```

## 3. 文構造

### 3.1 体言止めの制限

1記事に1〜2回まで。連続使用は禁止。

```
❌（連続使用）
興味深いのは、値上げニュースが続いていること。
そして重要なのは、価格決定力を持つ企業が少ないこと。

✅
興味深いことに、値上げニュースが相次いでいます。
そして重要なのは、価格決定力を持つ企業が少ないという点です。
```

### 3.2 主語の省略

「私は」を毎文入れると不自然。1セクションに1〜2回が目安。

```
❌ 私はプロダクトを作っている。私はこの動きに注目している。私は今週…
✅ プロダクトを作っている立場として、この動きには注目しています。今週は…
```

### 3.3 文の長さ

1文は40〜80文字が適切。100文字超は2文に分割する。

### 3.4 接続詞のバリエーション

同じ接続詞の連続使用を避ける。

- 逆接: しかし / 一方で / ただ / とはいえ / もっとも
- 順接: そして / また / さらに / 加えて
- 因果: つまり / なぜなら / そのため / したがって
- 転換: ところで / さて / 話を戻すと

## 4. 文体・トーン

### 4.1 です・ます調の統一

note記事のデフォルトは「です・ます」調。
見出し・太字強調・箇条書きは「だ・である」調でもOK。

```
✅ 本文: 「〜しています。」「〜ではないでしょうか。」
✅ 見出し: 「価格決定力を持つ企業だけが生き残る」
✅ 強調: 「**自分のプロダクトは顧客の価格決定力を高めているか？**」
```

### 4.2 口語レベルの統一

書き言葉と口語を混ぜない。

```
❌ データの越境移転は許容されません。これはマジでヤバい問題です。
✅ データの越境移転は許容されません。これは非常に深刻な問題です。
```

### 4.3 note特有のNGフレーズ

- 「いかがでしたか？」（典型的なSEO記事の定型句、noteで嫌われる）
- 「〜についてまとめてみました！」
- 「最後までお読みいただきありがとうございます」
- 「この記事が参考になったらスキをお願いします」

## 5. 読者視点

### 5.1 内部メモの混入禁止

```
❌ 「今週中にSkillプラットフォームへの組み込みを検討します。」
❌ 「TODO: この部分は後で詳しく調べる」
❌ 「関連プロジェクト: GBaseGTM / Skill System」
✅ 「こうした流れは、プロダクト設計にも大きな示唆を与えてくれます。」
```

### 5.2 文脈の補足

日本の読者が知らない固有名詞には最小限の説明を加える。

```
❌ 「元カラオケ会社がAI物流ツールをリリースしただけで…」
✅ 「ある企業がAI物流ツールをリリースしただけで…」
✅ 「米Symbotic社がAI物流ツールをリリースしただけで…」
```

### 5.3 「so what?」テスト

各セクションの末尾で「読者にとって何が重要なのか」が明確か確認。
データや事実の羅列だけで終わらず、読者への示唆を1文加える。
