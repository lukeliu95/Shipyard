# 公众号写作风格示例

## 好的开头 vs 坏的开头

### 示例 1：Signal 解读

**坏（分析师开头）：**
> 2026 年 2 月第三周，AI Agent 领域迎来了里程碑式的进展。GitHub 于 2 月 17 日正式发布了 Agentic Workflows 技术预览，将三大主流 AI Agent 集成到其 CI/CD 管道中。这一举措标志着 Agent 从社区概念正式升级为平台级基础设施...

**好（Builder 开头）：**
> GitHub 上周把三个 AI Agent 塞进了 Actions。Claude Code、Copilot、Codex，三家并排，一个平台。我的第一反应不是"Agent 时代来了"——那是分析师的标题。我的第一反应是：Agent 引擎正在变成水电煤，差异化要往上走了。而我一年前开始做的 Skill 系统，恰好就在"上面"那一层。

### 示例 2：Build Log

**坏（教程开头）：**
> 在当今 AI 快速发展的背景下，产品决策工具的需求日益增长。PM-Quill 是一款基于 AI Agent 的产品决策辅助工具，旨在帮助产品经理在编码之前完成结构化的需求分析...

**好（Builder 开头）：**
> PM-Quill 上线了。从第一行 spec 到发布，一共 23 天。中间最难的部分不是写代码——我不写代码——而是决定「不做什么」。

### 示例 3：方法论

**坏（学术开头）：**
> 随着 Vibe Coding 理念的兴起，越来越多的非技术背景从业者开始尝试利用 AI 辅助工具进行产品开发。本文将系统性地阐述非工程师如何构建完整的 AI 产品开发工作流...

**好（Builder 开头）：**
> 我不写代码。不是"不太会写"，是真的一行都不写。但过去三个月我 shipped 了三个 AI 产品。不是 demo，是有用户在用的东西。很多人问我怎么做到的，这篇就把方法讲清楚。

## 语气对照

| 场景 | 分析师写法 ❌ | Builder 写法 ✅ |
|------|-------------|----------------|
| 引用数据 | "据麦肯锡最新报告显示，Agent 经济规模将达 2.9 万亿美元" | "McKinsey 给 Agent 经济算了个数：2.9 万亿。这个数字准不准不重要，重要的是连咨询公司都开始给 Agent 标价了" |
| 做决策 | "经过综合评估，我们认为本地化方案更具可行性" | "我选了本地方案。原因很简单：日本客户对数据出境极度敏感，云端方案在他们那里根本过不了合规" |
| 预判趋势 | "我们预计 2026 年下半年将迎来 Agent 应用的爆发期" | "我觉得今年下半年会有一波 Agent 产品集中上线。不是预测，是因为我认识的好几个团队都在做，都计划 Q3 发布" |
| 总结 | "综上所述，非工程师在 AI 时代具有独特的竞争优势" | "所以我的结论是：不会写代码不是劣势。Agent 时代需要的是定义任务的能力，而这恰好是产品人一直在练的" |

## 段落节奏示例

**好的节奏（长短交替）：**

> 上周有一条数据让我想了很久。

> Temporal 拿了 3 亿美金，估值 50 亿。做的事情不性感——Agent 执行过程中断了怎么恢复、失败了怎么重试。但他们的收入同比增长了 380%。这意味着什么？意味着 Agent 现阶段的失败率高到需要一个 50 亿美金的公司专门来兜底。

> 这让我对自己做的事更有信心了。

> 因为 PM-Quill 解决的问题，在 Temporal 的上游。Temporal 解决的是"Agent 跑着跑着挂了怎么办"，PM-Quill 解决的是"Agent 应该跑什么"。如果连"跑什么"都没定义清楚，Temporal 再强也救不了你。

**坏的节奏（均匀中等）：**

> 上周 Temporal 获得了 3 亿美金的融资，估值达到了 50 亿美金。这家公司主要解决 Agent 执行过程中的可靠性问题。他们的收入同比增长了 380%，说明市场需求非常强劲。这意味着 Agent 的失败率还很高，需要专门的基础设施来保障。PM-Quill 解决的问题在 Temporal 的上游，即定义 Agent 应该执行什么任务。如果任务定义不清楚，即使有 Temporal 也无法解决根本问题。
