# 中文素材 → 微信公众号文章生成器

将中文素材（简报数据、Build Log、思考碎片、分析洞察）转化为可发布的微信公众号文章。
不是简单整理，而是**以 Builder 视角重新组织和撰写**。

## 使用时机

- 用户提供中文素材并要求生成公众号内容
- 用户提到"公众号""微信""wechat""周记""方法论"
- 内容线为 signal / build_log / methodology 且目标平台为微信

## 核心原则

公众号内容不是 Substack 的中文翻译，也不是 note 的中文版。它有独立的读者群体和内容策略。

| 维度 | 公众号定位 |
|------|-----------|
| 主阵地 | 方法论沉淀（Methodology）+ 行业洞察 |
| 语气 | 专业但讲人话，有温度，不学术 |
| 视角 | Builder 第一人称，"我做了/我决定了/我觉得" |
| 读者 | 非工程师背景但想做 AI 产品的人（PM、设计师、创始人） |
| 禁忌 | 分析师报告语气、技术教程风格、新闻搬运 |

## 工作流

### Step 1: 素材分析

从输入内容中提取：

- **核心主题** — 这篇文章要说什么
- **内容线** — signal / build_log / methodology
- **Builder 连接** — 跟 Luke 正在做的产品有什么关系
- **读者价值** — 读者看完能带走什么（方法、视角、行动项）
- **mckinsey-analyst 洞察** — 如有前置分析，提取关键因果链和战略启示

### Step 2: 确定文章类型

| 类型 | 适用场景 | 结构 |
|------|---------|------|
| **AI 造物周记** | 每周常规，signal + build_log 混合 | 本周关键信号 → 跟我在做的事有什么关系 → 本周 shipped 了什么 → 下周计划 |
| **产品决策故事** | 有普适性的 build_log | 我在做什么 → 遇到了什么选择 → 选了什么放弃了什么 → 为什么 → 结果 |
| **方法论长文** | methodology 线，月更 | 问题/痛点 → 我的方法 → 具体步骤 → 实际案例 → 适用边界 |
| **Signal 解读** | 强信号需要展开 | 发生了什么（1-2句）→ 跟产品人有什么关系 → 我打算怎么做 → 你可以怎么做 |

### Step 3: 撰写

遵循下方的写作规范和质量标准进行撰写。

### Step 4: 质量自检

运行质量检查清单（见下方），通过后输出。

---

## 写作规范

### 标题

- 15-30 字，不超过 35 字
- 要有信息量，不做标题党
- 可用「」强调关键词
- 不用问号开头的疑问句标题（"为什么 XX？"可以用，但不能滥用）

**好标题：**
- PM-Quill 上线了：我为什么要做一个"写代码之前"的工具
- AI 造物周记 W08：恐慌里藏着产品人的机会
- 不写代码怎么做 AI 产品——我的工具链全景

**坏标题：**
- 震惊！一个设计师竟然做出了 AI 产品
- 2026 年 AI Agent 赛道深度分析报告
- AI 时代，你准备好了吗？

### 开头（前 3 句）

前 3 句决定读者是否继续读。规则：

1. **直接切入**，不要"大家好""最近""前段时间"
2. **给一个具体的钩子** — 数据、事件、决策、问题
3. **建立"跟我有关"的连接** — 读者在第 3 句之前要感到"这跟我有关"

**好的开头：**
> 上周三，PM-Quill 正式上线了。从第一行 spec 到发布，一共 23 天。中间最难的部分不是写代码——我不写代码——而是决定「不做什么」。

**坏的开头：**
> 随着 AI 技术的快速发展，越来越多的产品人开始关注如何利用 AI 提升工作效率。本文将从产品设计师的视角，探讨...

### 正文

- **段落节奏：** 3-5 句一段，长短段交替
- **口语化但不随意：** "我觉得""说实话""讲个具体的"可以用，但不要每段都用
- **用具体代替抽象：** 不说"提升效率"，说"从 3 天缩短到 2 小时"
- **数据当佐料：** 引用数据时给出来源，但不要堆数据
- **小标题：** 全文 3-5 个小标题，每个小标题是一个完整意群
- **加粗：** 全文 3-5 处，只用于核心观点句
- **引用块：** 用于自我反思、关键判断、或内心独白（每篇 1-2 处）

### 结尾

- 2-3 句收尾，回到核心观点
- 可以给一个行动项或思考题
- 不要"以上就是""希望对你有帮助""欢迎点赞关注"
- 可以预告下周内容（如果是系列）

### 字数

| 文章类型 | 字数范围 |
|---------|---------|
| AI 造物周记 | 1500-2500 字 |
| 产品决策故事 | 1500-3000 字 |
| 方法论长文 | 2500-4000 字 |
| Signal 解读 | 1200-2000 字 |

## 语气校准

### 对的语气（Builder 讲话）

- "我觉得这个方向值得试"
- "说实话，这个决定我犹豫了两天"
- "数据很好看，但我更在意的是另一件事"
- "我选了 A 放弃了 B，原因是..."
- "如果你也是非工程师背景，这个方法可能对你有用"

### 错的语气（分析师/教授/营销号）

- "我们认为市场趋势表明..."
- "纵观 2026 年 AI 赛道..."
- "根据麦肯锡最新报告显示..."
- "本文将系统性地分析..."
- "不得不说，这是一个划时代的..."
- "让我们一起来看看..."

### 禁用表达清单

| 禁用 | 替代 |
|------|------|
| "让我们一起来看看" | 直接开始讲 |
| "不得不说" | 删除，直接说 |
| "纵观/总的来说" | 用具体判断代替 |
| "赋能" | "帮到""用在" |
| "抓手" | "切入点""方法" |
| "打法" | "做法""策略" |
| "底层逻辑" | "根本原因""核心逻辑" |
| "闭环" | "完整流程""串起来" |
| "对齐" | "统一认识""确认清楚" |
| "颗粒度" | "细节程度""具体到什么程度" |
| "沉淀" | "积累""留下来" |
| "链路" | "流程""路径" |
| "心智" | "认知""印象" |
| "势能" | "积累的优势""影响力" |

## 系列化模板

### AI 造物周记（每周）

```markdown
# AI 造物周记 W{XX}：{本周关键词}

{开头：本周最值得说的一件事，2-3句}

## 本周信号：{信号主题}

{信号事实 1-2 句}
{跟我在做的东西有什么关系}
{我打算怎么做 / 为什么不做}

## 本周 shipped

{做了什么，遇到了什么选择，结果怎样}

## 下周计划

{1-3 个具体的事}

---
{系列说明：这是「AI 造物周记」系列第 X 篇...}
```

### 非工程师 AI 产品手册（月更）

```markdown
# {方法论主题}

{开头：一个具体的问题或场景}

## 问题

{为什么这个问题值得专门写一篇}

## 我的方法

{核心方法 + 具体步骤}

## 实战案例

{来自 PM-Quill / GBaseGTM / Skill 系统的真实案例}

## 适用边界

{什么时候这个方法不好用}

---
{系列说明：这是「非工程师 AI 产品手册」系列第 X 篇...}
```

## 输入处理

### 简报数据 → 公众号
- 筛选跟 Builder 相关的信号，忽略纯投资/宏观信号
- 每条信号都要连接到"我在做的事"
- 不做数据搬运，数据只是佐料

### Build Log → 公众号
- 提取有普适性的设计决策
- 把内部过程翻译成读者能共鸣的叙事
- 重点是"为什么这么选"而不是"做了什么"

### mckinsey-analyst 洞察 → 公众号
- 因果链直接变成文章的论证骨架
- 二阶效应变成"你可能没想到的是..."
- 战略启示变成"对产品人意味着什么"
- 注意：不要暴露分析框架本身，要消化后自然表达

### 思考碎片 → 公众号
- 碎片需要补充论据和案例
- 一个碎片通常不够一篇，需要组合
- 保持原始碎片的直觉和锐度，不要修饰掉

## 质量自检清单

出力前必须确认：

- [ ] 开头 3 句是否直接切入？（没有"大家好""随着XX的发展"）
- [ ] 是否从"我做了/我决定了"出发？（不是"市场发生了"）
- [ ] 读起来像 Builder 在说话，还是分析师在写报告？
- [ ] 有没有具体的产品决策、设计选择、或 shipping 进展？
- [ ] 数据和信号是佐料，不是主菜？
- [ ] 有没有用到禁用表达？（赋能、抓手、打法、底层逻辑等）
- [ ] 小标题是否有信息量？（不是"分析""总结"这种空标题）
- [ ] 加粗是否控制在 3-5 处？
- [ ] 字数是否在目标范围内？
- [ ] 结尾是否干净？（没有"希望对你有帮助""欢迎关注"）
- [ ] 对非工程师读者友好？（没有无意义的技术术语）
