# 从 Vibe Coding 到 Agentic Engineering：中文开发者指南

> 一年前，Karpathy 随手发了条推文，创造了 "vibe coding"。一年后，他亲手埋葬了它。
> 取而代之的叫 Agentic Engineering —— 一个正在重新定义「写代码」这件事的新范式。

---

## 一条推文引发的范式之争

2025 年 2 月 2 日凌晨，Andrej Karpathy 发了一条推文。

他说自己发现了一种新的编程方式，叫 "vibe coding"。大意是：完全靠感觉写代码，不读 diff，不管代码长成什么样，报错了就复制粘贴给 AI，能跑就行。

这条推文他自己都没当回事。

但互联网不这么想。"Vibe coding" 一夜之间成了现象级词汇，上了维基百科，成了 Karpathy 的「重大文化贡献」。全世界的开发者开始 vibe coding，用 Cursor、用 Claude，靠感觉写出一个又一个 demo。

一年后，2026 年 2 月 4 日，Karpathy 在 vibe coding 一周年时又发了一条推文。

这次他说的是：

> "99% 的时间不再直接写代码，而是编排 agents，作为监督者存在 —— 我称之为 agentic engineering。用 engineering 这个词，是因为这里面有艺术、有科学、有专业技能。"

他亲手给 vibe coding 办了场体面的葬礼，然后推出了继任者。

---

## Vibe Coding 死于什么

Vibe coding 很爽。你不用理解代码，不用读文档，甚至不用碰键盘 —— 对着麦克风说话就能写出一个网站。

但它有一个致命问题：**只能做玩具**。

Karpathy 自己也承认，vibe coding "对周末项目还行"。一旦你想拿它做正经产品、赚真金白银，问题就来了：

**代码失控。** Karpathy 说"代码增长到超出我的理解范围"。一个你不理解的系统，就是一颗定时炸弹。

**安全裸奔。** 研究显示，纯 vibe coding 的项目比传统开发多 40% 的安全漏洞。你 "Accept All" 的那些代码里，可能藏着 SQL 注入和 XSS。

**无法迭代。** 代码是活的，需要维护、修 bug、加功能。如果你连代码长什么样都不知道，怎么迭代？

用物理学的话说：**vibe coding 的熵在失控增长**。没有外力介入，它只会越来越混乱，直到崩溃。

## Agentic Engineering：编排者的时代

2026 年 1 月 21 日，Anthropic 发布了一份 18 页的报告，标题是《2026 Agentic Coding Trends》。这份报告用企业级的数据，讲清楚了一件事：

**写代码这件事，正在从「手写」变成「编排」。**

什么意思？

以前，你是厨师，亲手切菜、炒菜、摆盘。现在，你是主厨，告诉三个厨师分别做什么菜，你负责试味、调整、把控出品质量。

以前，你对着编辑器一行一行敲代码。现在，你对着多个 AI agents 说清楚目标、约束、质量标准，它们去执行，你负责审核和决策。

这就是 agentic engineering。

**和 vibe coding 的本质区别在哪？**

| | Vibe Coding | Agentic Engineering |
|---|---|---|
| **你的角色** | 实验者，靠感觉 | 架构师 + 监督者 |
| **对代码的态度** | "不读 diff，Accept All" | 战略性审查，把控质量 |
| **适用场景** | 周末项目、demo | 生产级产品 |
| **核心技能** | 会说话就行 | 编排、分解任务、质量控制 |
| **目标** | 能跑就行 | 保留 AI 杠杆，不牺牲质量 |

Karpathy 自己总结得最好：

> "目标是利用 agents 的杠杆效应，但不在软件质量上做任何妥协。"

## 递弱代偿：为什么人类反而更重要了

这里有一个反直觉的现象：**AI 越强，人类越不可替代。**

用递弱代偿理论解释 ——

物种越高级，自身的生存度越低，越依赖外部手段来代偿。单细胞生物什么都能干，人类离了工具什么都干不了。但正因为如此，人类发展出了最复杂的工具体系和协作机制。

AI agents 也是一样。它们越强大，能自主完成的事情越多，就越需要一个「编排者」来：

- **定义方向** —— agent 不知道该往哪走
- **把控质量** —— agent 不知道什么是"好"
- **做取舍** —— agent 不知道什么该做什么不该做
- **承担责任** —— agent 不为结果负责，你要

Anthropic 的报告里有一个数据特别说明问题：**开发者在 60% 的工作中使用 AI，但只全权委托 0-20% 的任务，并且在 80-100% 的委托任务上保持主动监督。**

这不是因为 AI 不够强。而是因为：编排本身就是核心价值。

就像一个交响乐团，最贵的不是乐器，是指挥。

## Anthropic 报告：8 个正在发生的趋势

Anthropic 的报告基于真实企业数据，这些不是预测，是已经在发生的事：

### 1. 开发者角色正在变化

工程师现在 60% 的工作都有 AI 参与。但他们的工作重心从"写代码"转向了：
- 系统架构设计
- Prompt 工程和上下文管理
- Agent 产出的审核和验证
- 高风险技术决策

**翻译成人话：** 以前你是工人，现在你是工头。

### 2. 多 Agent 协作成为标准

不再是一个 AI 帮你写代码，而是多个专门化的 agents 在不同的上下文窗口里并行工作。

人力资源公司 Fountain 用多 agent 架构把筛选速度提升了 50%，候选人转化率翻了一倍。

### 3. 人类监督在智能化

Agents 现在能自主完成 20 个连续动作才需要人类介入（比之前翻了一倍）。它们学会了在关键节点主动请求人类判断。

### 4. 非技术人员开始写代码

最大的变化不在工程团队，而在工程团队之外。

Zapier 全公司 97% 的人都在用 AI 编程 —— 包括市场、运营、HR、法务。传统的"找工程师排期"的瓶颈消失了。

**这意味着什么？** 产品经理、设计师、运营都可以自己做工具了。Luke 的 vibe coding 方向，就是这个趋势的一部分。

### 5. 效率数据惊人

- **乐天**：产品上线周期从 24 天缩短到 5 天，提速 79%
- **TELUS**：57000 名员工节省了 50 万小时，创建了 13000 个定制 AI 方案
- **Claude Code**：在 1250 万行代码的项目中，7 小时完成任务，准确率 99.9%

### 6. 安全成为第一优先级

双刃剑：AI 让防御更强，但也降低了攻击门槛。安全必须从第一天就内嵌到设计中，不能事后补。

## 中国开发者怎么上手

理论讲完了，讲实操。

### 第一步：选工具

| 工具 | 适合谁 | 特点 |
|------|--------|------|
| **Claude Code** | 有命令行习惯的开发者 | 本地运行，直接访问文件系统，agent 能力最强 |
| **Cursor** | 习惯 IDE 的开发者 | 编辑器集成，上手快 |
| **国产模型（GLM-5、Kimi K2.5）** | 需要离线/隐私优先的场景 | 本地部署，中文理解好 |

建议：从 Claude Code 开始。Karpathy 说它是"第一个令人信服的 LLM Agent 示范"。

### 第二步：学会分解任务

Agentic engineering 的核心技能不是写 prompt，是**任务分解**。

不好的做法：
```
"帮我做一个电商网站"
```

好的做法：
```
1. 先设计数据模型（用户、商品、订单）
2. 搭建 API 框架（用 Next.js）
3. 实现商品列表页
4. 实现购物车逻辑
5. 实现结账流程
6. 加上支付集成
7. 写测试
```

每一步都是一个明确的、可验证的任务。Agent 擅长做明确的任务，不擅长做模糊的大目标。

### 第三步：建立审核习惯

Vibe coding 的毛病是 "Accept All"。Agentic engineering 的做法是：

- **每次 agent 完成一个步骤，review 一下**
- **关键决策自己做**（技术选型、架构设计、安全策略）
- **建立自动化测试**，让代码自己证明自己对不对
- **安全检查前置**，不是做完再补

### 第四步：用文件系统做记忆（进阶）

Agent 最大的问题是没有记忆。每次会话是全新的。

Bill_v1 的解决方案：用文件系统代偿记忆。

```
CLAUDE.md          → 告诉 AI 它是谁、怎么工作
loop/state.md      → 上次做到哪了
.features/         → 每个模块的知识积累
scheduler/         → 定时自动执行
```

这套方案不需要数据库、不需要后端服务、不需要额外费用。纯 Markdown 文件，Claude Code 原生支持。

实际效果：两天内完成了 7 轮信息扫描，每天自动执行，扫描结果通过邮件推送。AI 记住了上次的发现，这次接着分析。

## 这波趋势里什么能赚钱

### 1. 教程和内容

中文世界对 agentic engineering 的系统性内容几乎是空白。谁先做出高质量的中文指南、视频教程、实战课程，谁就能吃到第一波红利。

参考：Anthropic 报告中文解读、Karpathy 方法论本土化、中国工具 + 海外方法论的结合。

### 2. 垂直场景的 Agent 方案

不是所有人都会编排 agents。帮特定行业（电商、教育、法律、金融）搭建定制化的 agent 工作流，是一个很大的市场。

Anthropic 的数据：agent 市场 2025 年 78 亿美元，2030 年预计 526 亿美元，年增长率 46.3%。

### 3. 安全审计工具

AI 让人人都能写代码，但不是人人都能写安全的代码。AI agent 安全审计工具是刚需。GitHub 上的 shannon（AI 安全审计工具）两周涨到 21K 星，说明需求爆发了。

### 4. 非技术人员的 AI 编程培训

Zapier 97% 的员工都在用 AI 编程。中国企业也会走到这一步。教产品经理、运营、市场人员用 AI 做工具，是一个巨大的培训市场。

## 写在最后

从 vibe coding 到 agentic engineering，表面上是工具的进化，本质上是**人的角色升级**。

你不需要更会写代码 —— 你需要更会**编排**、更会**判断**、更会**定义问题**。

这些恰恰是人类最擅长的事。

AI 不会替代你。但会用 agentic engineering 的人，会替代不会用的人。

现在开始学，还来得及。
