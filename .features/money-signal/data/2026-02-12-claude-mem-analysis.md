# claude-mem 深度分析 — 2026-02-12

## 它到底是什么

claude-mem 是一个 Claude Code 插件，做的事情很简单：**让 Claude Code 在会话之间不失忆。**

它不是给普通用户用的，是给用 Claude Code 写代码的程序员用的。

## 核心机制（很聪明）

### 1. 自动捕获，不需要用户动手
- 通过 Claude Code 的 hook 系统（生命周期钩子）自动捕获所有工具使用
- 每次 Claude 读文件、执行命令、搜索代码，都被记录下来
- 用户完全不需要手动"保存记忆"

### 2. AI 压缩，不是原样存储
- 捕获的原始数据通过 Claude Agent SDK 压缩
- 提取出：标题、叙述、关键事实、涉及的文件
- 压缩后存到 SQLite

### 3. 渐进式披露（三层搜索），省 token
这是它最聪明的设计：
- **第一层：索引** — 只返回 ID 和摘要（~50-100 tokens）
- **第二层：时间线** — 围绕某个节点的上下文（~500 tokens）
- **第三层：详情** — 完整信息（~1500 tokens）

传统 RAG 需要 20,000+ tokens，它只要 ~3,000。**省了 10 倍。**

### 4. 文件夹级别的 CLAUDE.md 自动生成
- 在每个项目文件夹自动生成 CLAUDE.md
- 记录最近在这个目录里做了什么
- 下次进来直接读到上下文

## 技术栈

| 组件 | 技术 |
|------|------|
| 语言 | TypeScript |
| 运行时 | Node.js 18+ / Bun |
| 存储 | SQLite + FTS5 全文搜索 |
| HTTP 服务 | Express.js (端口 37777) |
| AI 压缩 | Claude Agent SDK |
| 前端 | React（Web Viewer） |
| 语义搜索 | ChromaDB（可选） |

## 对 MemoBrain 的启发

### 可以借鉴的
1. **渐进式披露** — 不是把所有记忆一股脑注入，而是分层。先给 AI 看索引，需要时再给详情。这对我们也适用，记忆多了之后全部注入太浪费 token。
2. **AI 压缩** — 用户可能保存很长的记忆，可以用 AI 压缩成更精炼的版本再注入。
3. **自动捕获** — claude-mem 不需要用户手动保存，自动从对话中提取。MemoBrain 现在是手动的，后续可以加自动提取。
4. **文件夹上下文** — 按"场景"组织记忆，不同项目/话题有不同的记忆集。

### 我们的差异化
1. **claude-mem 只能在 Claude Code 里用** — 我们在浏览器里，跨 ChatGPT/Claude/Gemini
2. **claude-mem 面向程序员** — 我们面向普通用户
3. **claude-mem 需要命令行安装** — 我们是 Chrome 扩展，一键安装
4. **claude-mem 是英文** — 我们中文优先

### MemoBrain 下一步可以加的功能（按优先级）
1. **P1: 智能注入** — 不注入全部记忆，根据当前对话内容自动匹配最相关的 3-5 条
2. **P1: 自动提取** — 从 AI 对话中自动识别值得保存的信息（"我是产品经理"这种）
3. **P2: 记忆压缩** — 多条相关记忆压缩成一条精炼版本
4. **P2: 场景分组** — 按项目/话题分组记忆，不同场景注入不同记忆
5. **P3: 渐进式披露** — 先注入摘要，AI 需要详情时再补充

## 总结

claude-mem 做得很好，但它解决的是程序员在 Claude Code 中的记忆问题。

MemoBrain 解决的是**普通人在 AI 聊天（网页版）中的记忆问题**。

两个产品的目标用户几乎不重叠，不构成直接竞争。claude-mem 的技术思路（渐进式披露、AI 压缩、自动捕获）是我们可以借鉴的。
