# 深度挖掘：AI 记忆赛道 — 2026-02-12

## 一、这个市场在解决什么问题

AI 助手有"失忆症"。每次新会话，它忘了你是谁、你在做什么、上次聊到哪。

你每天重复告诉 AI 同样的事："我是产品经理"、"我用 React"、"上次我们在做登录功能"。这是巨大的时间浪费和体验断裂。

**核心痛点：AI 的记忆和人的记忆之间的鸿沟。**

## 二、竞品地图（6 个主要玩家）

### Tier 1: 融资型创业公司

| 公司 | 融资 | 定位 | 做法 |
|------|------|------|------|
| **Mem0** | $24M（Series A，2026.2） | AI 应用的记忆层 | 混合存储（图+向量+KV），API 接入，开源+云服务 |
| **Supermemory** | $2.6M（Seed） | 通用记忆 API | 用户画像+语义理解，跨平台，19 岁创始人 |
| **Letta** | Felicis 领投 | 有状态 AI agent 平台 | 基于 MemGPT 论文，agent 自己管理记忆 |

### Tier 2: 开源工具/插件

| 工具 | Stars | 定位 | 做法 |
|------|-------|------|------|
| **claude-mem** | 12.9K+ | Claude Code 记忆插件 | 自动捕获+压缩+注入，SQLite 本地存储 |
| **AI Context Flow** | - | 跨平台浏览器扩展 | 记忆桶概念，支持 ChatGPT/Claude/Gemini/Perplexity |
| **Memory Plugin** | - | 轻量记忆插件 | 支持多个 AI 工具，简单 KV 存储 |

### Tier 3: 平台自带（不完善）

- **ChatGPT Memory**: 容量小（约 1200-1400 词），不可控
- **Claude Projects**: 文件级上下文，手动管理
- **Cursor Rules + Memory Bank**: 规则文件 + markdown 记忆

## 三、技术路线对比

| 路线 | 代表 | 优点 | 缺点 |
|------|------|------|------|
| **API 记忆层** | Mem0 | 通用性强，一行代码接入 | 面向开发者，普通人用不了 |
| **Agent 自管理** | Letta/MemGPT | 最智能，agent 自己决定记什么 | 复杂度高，需要整个 agent 框架 |
| **本地插件** | claude-mem | 隐私好，自动化高 | 只支持单一工具（Claude Code） |
| **浏览器扩展** | AI Context Flow, Mem0 Chrome | 跨平台，用户友好 | 浏览器限制，功能受限 |
| **文件系统** | Cursor Memory Bank | 简单可控，用户可编辑 | 手动维护，不智能 |

## 五、市场空白分析

### 空白 1: 中文市场几乎空白
- 以上所有产品都是英文优先
- 中国 AI 用户量巨大（Gemini 7.5 亿月活，大量是中国用户）
- 没有一个中文优先的 AI 记忆产品

### 空白 2: "普通人"解决方案缺失
- Mem0 面向开发者（需要写代码接入）
- Letta 面向技术型用户（需要部署 agent 框架）
- claude-mem 面向 Claude Code 用户（程序员）
- 普通的 AI 聊天用户（用 ChatGPT/Claude 网页版的人）没有好用的方案

### 空白 3: 记忆的"可视化和管理"
- 现有工具都是"自动记"，但用户看不到 AI 记住了什么
- 没有好的界面让用户管理、编辑、组织 AI 的记忆
- "我的 AI 到底了解我多少"这个问题没有答案

### 空白 4: 垂直场景的专用记忆
- 现有方案都是通用的
- 没有专门为"vibe coding"、"内容创作"、"产品设计"等场景优化的记忆工具

## 六、Luke 的机会评估

### 机会 A: 中文 AI 记忆浏览器扩展（推荐）

**做什么：** 一个 Chrome 扩展，让 ChatGPT/Claude/Gemini/豆包 等 AI 工具有持久记忆，中文优先。

**为什么适合 Luke：**
- 产品设计是核心差异化（现有产品 UI/UX 都很糙）
- 浏览器扩展技术门槛不高，vibe coding 可以搞定
- 中文市场空白，先发优势明显
- 可以先做一个简单版本（像 Memory Plugin），再迭代

**MVP 预估：** 2-3 周
**变现：** Freemium（免费 100 条记忆，付费无限）月费 $5-10
**风险：** 平台自带记忆功能可能越来越好

### 机会 B: AI 记忆可视化仪表盘

**做什么：** 一个 web 应用，连接你的各种 AI 工具，展示"你的 AI 对你了解多少"，可以管理和编辑记忆。

**为什么适合 Luke：**
- 纯产品设计问题，UI/UX 决定成败
- 可以基于 Mem0 的开源 API 构建
- "AI 了解你多少"这个概念有传播性

**MVP 预估：** 3-4 周
**变现：** SaaS 月费
**风险：** 依赖第三方 API

### 机会 C: Vibe Coder 专用记忆工具

**做什么：** 专门为 vibe coding 场景设计的记忆系统 — 记住你的设计偏好、常用技术栈、项目上下文。

**为什么适合 Luke：**
- Luke 自己就是目标用户
- 比通用记忆更聚焦，可以做得更深
- vibe coding 市场在爆发（$4.7B → $12.3B）

**MVP 预估：** 2 周
**变现：** 作为 Claude Code / Cursor 插件卖，或者独立 SaaS
**风险：** 市场偏小，天花板不高

## 七、结论

AI 记忆赛道**确认有钱**（Mem0 刚拿 $24M）。市场需求**确认真实**（claude-mem 3 天 5K stars）。

但头部玩家都在做"面向开发者的基础设施层"。**面向普通用户的产品层**还是一片空白。

这正好是 Luke 的能力圈：**不做底层，做产品层。不做英文市场，做中文市场。不做通用方案，做具体场景。**

**我的建议：机会 A（中文 AI 记忆扩展）优先级最高。** 市场空白最大，技术门槛最低，Luke 的产品设计能力最能发挥。
